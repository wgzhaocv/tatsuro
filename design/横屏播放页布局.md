# 全屏播放页（歌词页）在「宽而矮」画面上的重做

状态：**未实施，待站主拍板**。写于 2026-08-07。
涉及文件：`components/player/full-player.tsx`、`components/player/lyrics-panel.tsx`、`app/globals.css`。

---

## 一句话

播放页布局只按**宽度**分叉（`sm` / `lg`），所以"宽度够但高度不够"的画面掉进了为高窗口设计的那套里。缺的是**高度**这个维度。

## 问题：`lg` 的通栏控制条吃掉了纵向预算

现在的 `lg` 网格（`full-player.tsx:232-316`）：

```
┌──────────┬───────────────────┐
│  封面     │      歌词          │  row 1 = 1fr
├──────────┴───────────────────┤
│ 频谱 · 进度条 · 传输 · 音量     │  row 2 = auto ← 通栏
└──────────────────────────────┘
```

row 2 通栏且不可压缩，固定开销约 400px：

| 组件 | 高度 |
|---|---|
| header（关闭 + 操作按钮） | ~64 |
| stage 上下 py-8 | 64 |
| `Spectrum h-12` | 48 |
| SeekBar（`mt-7` + 轨道 + 时间码） | ~70 |
| Transport（`mt-4` + 64px 播放键） | 80 |
| VolumeControl（`sm:` 起显示） | ~52 |
| `gap-y-6` | 24 |
| **合计** | **~400** |

iPad mini 横屏 744 高 → 歌词行只剩 **~342px**；Safari 带工具条 ~290。`LyricsPanel` 自身还有 `py-14`（112px）+ 上下各 3rem 渐隐遮罩，**实际能读 2–3 行**。

横向同时在浪费：控制条被拉成 1133px 宽的一条，右侧大片空白——拿宽度换了最缺的高度。

## 全画面盘点

| 画面 | 视口 | 现在走哪套 | 结果 |
|---|---|---|---|
| 手机竖屏 | 390×844 | 竖排 + 翻面 | ✓ |
| iPad 竖屏 | 744×1133 / 820×1180 | 竖排 + 翻面 | ✓（宽度略浪费但成立） |
| 大桌面 | 1920×1080 | 明信片（通栏控制条） | ✓ |
| **iPad 横屏** | **1133×744 / 1180×820** | 明信片 | ✗ 歌词只剩 2–3 行 |
| **13" 笔记本** | **1440×790** | 明信片 | ✗ 同上，轻一点 |
| **手机横屏** | **844×390** | 竖排 + 翻面 | ✗✗ 封面 172px，控制条溢出，整页要滚 |

出问题的三格是**同一个病**，所以一个方案覆盖。

参考尺寸（CSS 逻辑像素，横屏）：iPad mini 6/7 = 1133×744；iPad mini 1–5 = 1024×768；iPad 10/11 代 = 1180×820；iPad 9 代 = 1080×810；iPad Air/Pro 11" = 1194×834；iPad Pro 12.9" = 1366×1024。全部落在 `lg`（1024–1279），只有 12.9" 进 `xl`。

## 设计目标：iPad 平放 ≠ 矮桌面窗口

站主的判断：**iPad 横屏平放播放是很普遍的需求**。这个场景是"桌面显示器"——人在 50–80cm 外斜着看，不握设备，偶尔伸手点一下。按**跟唱 / 环境显示**来设计，不是把桌面布局压进去。

三点差别：

1. **歌词是主角**。17px 在手持距离够，平放斜看偏小 → 该到 **20px**，当前行 **22px + medium**，行距放开。右栏 ~700×600 撑得住。
2. **封面缩小让位**。`min(18rem,30vh)` → `min(13rem,28vh)`（~200px）。平放时封面的作用是提供氛围色（`AlbumAmbient` 已经在做），不必当视觉中心。
3. **控制件按"伸手点"留尺寸**。播放键 64 不动、前后曲 48 不动；`Spectrum` 和音量条去掉（一个是装饰，一个 iPad 有硬件键，合计白吃 ~100px 高）。

## 方案：控制条收进左栏，歌词跨满高

```
┌──────────┬───────────────────┐
│  封面     │                   │
│  标题     │   歌词（满高 ~600）  │
│ 进度/传输 │                   │
└──────────┴───────────────────┘
```

触发条件从「宽度够」改成「高度不够」：

```css
/* app/globals.css，紧跟现有的 @custom-variant dark */
@custom-variant wide-short (@media (min-width: 640px) and (max-height: 900px));
```

`max-height: 900` 覆盖横屏 iPad 全系（744–834）、13" MacBook 全屏（~790）、14" MBP（~880）；1080p+ 桌面（~940+）保持明信片构图。

**网格本身不用改**（rows 仍是 `[minmax(0,1fr)_auto]`），只改归属：

1. 控制条：去掉 `lg:col-span-full` → 该变体下 `col-start-1`（只占左栏）
2. `LyricsPanel`：该变体下加 `row-span-2`（跨两行 → 满高）
3. 封面 `lg:w-[min(18rem,30vh)]` → 该变体收到 `min(13rem,28vh)`
4. `Spectrum` 该变体下 `hidden`
5. `LineText` 字号加变体：17px → 20px，当前行 22px

## 三个决定（推荐值，可驳）

1. **加变体，不统一** —— 1080p+ 桌面保留通栏进度条的明信片构图，它在那儿是好的。代价是多一条代码路径。
   - 另一选择：全 `lg` 统一走左栏（Apple Music iPad 横屏就是这形态），少一套路径，丢掉大屏明信片感。
2. **音量条改 `(hover: hover)` 才显示** —— 触屏一律去掉，桌面留着。现在是 `sm:` 起显示，iPad 上纯浪费。
3. **手机横屏不单独优化，但让它落进同一变体**（条件已含 `min-width:640`，844×390 会命中）。套左栏后约：封面 109 + 标题 50 + 进度 70 + 传输 80 ≈ 310，塞得进 ~330 可用高度——**比现在溢出滚动好**。
   - 若之后要单独压一档，加第二级 `wide-tiny (max-height: 520px)`：去音量条、播放键 64→52、`mt-7/mt-4/mt-5` 收紧、header 强制 `flex-nowrap`（现在 `flex-wrap` 会让 "playing from" 换行吃掉 ~44px）。

## 边界

- 不动播放器状态机、不动数据层。纯布局 + 字号。
- 改完按 AGENTS.md 的规矩：双主题各看一遍，`/demo` 核对 token 无变化。
- 验证画面至少四个：1133×744（iPad mini 横）、1194×834（iPad Pro 11" 横）、1440×790（13" 笔记本）、1920×1080（回归，确认明信片没坏）。
