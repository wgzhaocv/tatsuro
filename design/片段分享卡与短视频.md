# 歌曲片段分享卡 + 音乐短视频（前端生成）— 备忘

> 2026-07-27 记。站主想法，**未排期**（ROADMAP Backlog #11）。现在没时间做，先把想法和技术结论完整记下，以后拿起来就能开工。
> UI **待想**（站主自己想），本文档只锁需求边界和技术路线。

## 一、想法是什么

选一段歌曲（比如副歌 15–30 秒），在站内生成两种可分享的东西：

1. **静态分享卡（歌词片段截图）** — 封面 + 歌词片段 + 曲名/专辑名的一张图。
   做成 **Noon Postcard 明信片形态** —— 这是设计系统名字的字面兑现：站主分享出去的就是一张"正午的明信片"。
2. **音乐短视频** — 片段音频 + 动态画面：封面环境光糊底、打轴歌词逐行点亮（卡拉OK 式）、波形律动之类。出一个能直接发微信/社交平台的视频文件。

**制作过程全部在前端浏览器里完成**（"用 wasm 之类的"——实际结论是首选连 wasm 都不用，见下）。

### 为什么前端是唯一合理的位置

- 后端是 Cloudflare Workers，**跑不了 ffmpeg**，没有服务端转码的位置；
- 前端生成 = 零后端成本、零存储成本，符合本站"白嫖免费额度"的一贯架构伦理；
- 用户浏览器的硬件编码器（WebCodecs）就是现成的转码农场。

### 手里已有的弹药（全部现成）

| 素材 | 在哪 | 用途 |
|---|---|---|
| 打轴歌词（带时间戳，lyrics_state 五态） | 后端 lyrics 接口 + `/studio` 打轴工具 | 卡拉OK 逐行点亮；分享卡的歌词片段；**按歌词行选段**的交互基础 |
| 封面 | `/stream/img/{coverId}` | 卡片主视觉；视频的环境光糊底（专辑详情页已有同款材质） |
| 双语曲名 | `nameLang(locale)` 体系 | 卡片/视频的文字层 |
| Noon Postcard 视觉系统 | DESIGN.md | 卡片就是明信片：色板、阴影、字体全部照搬 |
| 音频 | `/stream/new_play/{songId}`（opus） | 解码切段 → 视频音轨 + 波形 PCM |
| token 分享机制 | `lib/share.ts`（argot token） | 卡片/视频上可附回站深链或二维码（可选） |

## 二、技术路线（2026-07 时点的结论，开工时再验证）

### 2.1 静态分享卡 — 先做，便宜，独立成立

**Canvas 2D 直接画，不需要任何库/wasm。**

- 为什么不用 satori/html-to-image：OG 图已踩过 **satori 无 CJK 字体**的坑（ROADMAP #7）；Canvas 2D 用系统字体，日文（Hiragino Sans / Noto Sans JP）天然可用，`:lang(ja)` 那套字体策略照搬进 `ctx.font`。
- 流程：离屏 canvas 按明信片规格画（封面、歌词几行、曲名、站标）→ `canvas.toBlob('image/png')` → `navigator.share({files})`（移动端）/ 下载（桌面）。
- 尺寸建议出 2–3 档预设：方图 1080×1080、竖图 1080×1350（IG 系）、9:16 1080×1920（story/朋友圈封面）。

**已知的坑（提前记住）：**

- **封面跨域 canvas taint**：`/stream/img` 的响应目前没有 CORS 头。画进 canvas 后 `toBlob` 会抛 SecurityError。开工前先给 Worker 的 img 路由加 `Access-Control-Allow-Origin`（后端 `../yamashita-api` 一行事），前端 `new Image()` 要设 `crossOrigin = 'anonymous'`。
- 字体：卡片上如果要用 Quicksand（`font-display`），注意 `document.fonts.ready` / `FontFace.load()` 等字体就绪后再画，否则首次生成会 fallback 字体。

### 2.2 音乐短视频 — 首选 WebCodecs + mediabunny（不用 ffmpeg.wasm）

**输出目标：mp4（H.264 + AAC）** —— 发微信、各社交平台最不挑食的组合。

**管线：**

```
音频：fetch(opus 字节) → decodeAudioData（离线解码，整首 PCM）
      → 切出选段 → AudioEncoder 重编 AAC
      → 同一份 PCM 顺手算波形（降采样峰值数组）

画面：OffscreenCanvas（worker 里）逐帧画
      封面环境光糊底 + 打轴歌词逐行点亮 + 波形/进度
      → new VideoFrame(canvas, {timestamp}) → VideoEncoder（H.264，硬件加速）

封装：mediabunny 把两路 encoded chunk mux 成 mp4 → Blob → share/下载
```

- **mediabunny**：纯 TypeScript 的媒体读写库（mp4-muxer / webm-muxer 作者 Vanilagy 的后继项目），几十 KB，读写 mp4/webm、对接 WebCodecs 是它的本职。用它替代 ffmpeg.wasm 的 mux 环节。
- 帧率 24/30fps 足够；离线逐帧编码不受实时限制，30 秒片段几秒钟就能出片（有硬件编码时）。
- 逐帧画放 **worker + OffscreenCanvas**，别占主线程（生成时 UI 还要活着）。
- **音频解码必须走离线路径**（fetch 字节 → `decodeAudioData` 或 AudioDecoder），**绝对不碰正在播放的 `<audio>` 元素** —— iOS 上给播放元素接 Web Audio 会掐断 AirPlay（见 memory `ios-webaudio-breaks-airplay`），这是已经流过血的雷。

**兼容阶梯（feature-detect 逐级降）：**

1. **WebCodecs 全套可用**（Chrome/Edge 桌面、新 Safari）→ 上面的管线，最快最好。
   注意 iOS Safari：VideoEncoder 16.4 才有，**AudioEncoder 落地更晚**，两个都要探测；AAC 编码支持还因平台而异，探测 `AudioEncoder.isConfigSupported({codec:'mp4a.40.2'})`。
2. **WebCodecs 不在** → `canvas.captureStream(30)` + 播放选段进 `MediaStreamAudioDestinationNode` + **MediaRecorder**。
   缺点：只能**实时**录（30 秒片段等 30 秒）、码率控制粗、Chrome 出 webm / Safari 出 mp4（容器不统一）。能用，体验差一档。
3. **再不行** → 只提供静态分享卡（全平台无门槛，这也是先做卡的理由之一）。

**为什么不用 ffmpeg.wasm（除非走投无路）：**

- 体积 ~30MB，加载就劝退；
- 软编码慢（比 WebCodecs 硬编慢一个数量级）；
- 多线程版要求 **COOP/COEP（cross-origin isolation）**，整站开了会连坐封面、流媒体、MV 公开域的跨域加载 —— 对本站是伤筋动骨的代价。
- 它唯一的相对优势（万能容器/滤镜）本需求用不上。

### 2.3 版权口径

私享站（密码门 + noindex），熟人间分享 15–30 秒片段，敞口与现有的 token 分享链接同级。不做公开传播功能，不放大。

## 三、UI 留白（站主想，这里只放种子）

- **选段交互**：可以复用播放器进度条 + 打轴歌词做"**按歌词行选段**"——点/拖两行歌词圈出片段，比拖时间轴更贴这个站的气质，还天然对齐歌词行边界（视频里的卡拉OK 不会从半句开始）。
- **入口**：大概率挂在现有溢出菜单（`track-actions`）+ 全屏播放器,与 Share 并列或收进 Share 下一层。
- **生成过程本身可以是个小剧场**：进度不用假 spinner，可以直接把正在逐帧画的 canvas 预览出来——"制作过程放到前端"的另一层含义。
- 模板先只做一款（明信片），别一上来做模板选择器。

## 四、开工顺序（将来拿起来时）

1. 后端：`/stream/img` 加 CORS 头（一行，先做，卡和视频都依赖）。
2. 静态分享卡：Canvas 2D 画明信片 → share/下载。**独立可上线，先发这个。**
3. 选段交互（按歌词行选段），卡和视频共用。

5. 开工前重新核一遍兼容性现状（本文档写于 2026-07，WebCodecs/AudioEncoder 的 Safari 支持在快速变化，mediabunny 也在快速迭代）。
